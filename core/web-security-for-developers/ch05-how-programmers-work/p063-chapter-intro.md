# How Programmers Work - Chapter Introduction
(Source: PDF p. 63, tail PDF p. 64. The tail page text above the "Phase 1: Design and Analysis" heading belongs here; Phase 1 is WS-C05-002.)

## What the section covers
The opening framing of Chapter 5: why web development is iterative and needs discipline, what the Software Development Life Cycle is, and the roadmap of five phases plus dependency handling (PDF pp. 63-64).

## Meaning
- Building and maintaining a website is an ongoing, iterative process rather than a one-off goal. Rarely does a developer get every feature right first time. The product evolves, the codebase grows more complex, and developers keep adding features, fixing bugs and restructuring code; redesigns are routine (PDF p. 63).
- The Software Development Life Cycle (SDLC) is the process a development team follows when designing new site features, writing code, testing it and pushing out changes (PDF p. 64).

## Why it matters
- Changes must be made and rolled out in an orderly, disciplined way. Deadline pressure leads to shortcuts, and security vulnerabilities and bugs commonly creep in over time as a result (PDF p. 63).
- The book's claim: most vulnerabilities come from a lack of attention to detail, not from lack of development knowledge (PDF p. 63).
- A chaotic, messy SDLC makes it impossible to know which code is running and what its vulnerabilities are, which inevitably yields a buggy, insecure site. A well-structured one lets you find bugs and vulnerabilities early and protect the finished site from attack (PDF p. 64).

## How the chapter is organised
The chapter focuses on writing secure code by following the SDLC, and walks through five phases (PDF p. 64):
1. Design and analysis (WS-C05-002).
2. Writing code (WS-C05-003).
3. Pre-release testing (WS-C05-004).
4. The release process (WS-C05-005).
5. Post-release testing and observation (WS-C05-006).
It also touches briefly on securing dependencies, the third-party software a site uses (WS-C05-007), and ends with a summary (WS-C05-008) (PDF p. 64).
