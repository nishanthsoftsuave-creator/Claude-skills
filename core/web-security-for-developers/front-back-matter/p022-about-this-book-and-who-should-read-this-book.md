# About This Book and Who Should Read This Book
(Source: PDF p. 22. The heading "A Brief History of the Internet" begins lower on the same page and is covered in WS-I-003.)

## What the section covers
The author's central claim about how small the web-security problem space is, and who the book is written for and how each kind of reader should use it.

## Meaning
- The "big secret" of web security is that the number of web vulnerabilities is rather small, roughly few enough to fit in one book, and that the set barely changes from year to year (PDF p. 22).
- The book promises to teach every key threat a developer needs to know and to break down the practical defensive steps for a website (PDF p. 22).

## Who should read it
- Developers just starting out, whether they hold a computer science qualification, have finished a bootcamp, or are self-taught. The author recommends these readers go cover to cover, because everything in the book is described as essential and is explained plainly with clear examples. Preparing fully early saves trouble later (PDF p. 22).
- More experienced programmers. They can use it to fill gaps, treating it as a reference and dipping into whichever chapters look interesting, since you do not always know what you do not know. Senior programmers also have a duty to lead their team by example, which for web developers means following security best practice (PDF p. 22).

## Language neutrality
- The book is not tied to one programming language, though it gives recommendations for the major languages when needed (PDF p. 22).
- The reasoning: understanding web security helps whichever language you use, and since programmers often use several languages over a career, it is better to learn principles than to focus heavily on individual libraries (PDF p. 22).

## When and how to apply
INTERPRETATION: Newer developers read linearly; experienced ones use the chapter list in WS-I-004 to jump to the threat they want to revisit.
