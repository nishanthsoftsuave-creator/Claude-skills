# Foreword
(Source: PDF p. 3)

## What the section covers
The project's opening case for a separate, API-specific risk list next to the general OWASP Top 10, a note on how to read the document, and where to contribute.

## Why it matters
- The foreword presents the API as a foundational element of innovation in an app-driven world. It lists banks, retail and transportation, IoT, autonomous vehicles and smart cities as places where APIs now sit at the heart of mobile, SaaS and web applications, whether customer-facing, partner-facing or internal (PDF p. 3).
- By their nature, APIs expose application logic and sensitive data such as Personally Identifiable Information (PII), which is why they have become a growing target. The foreword's one-line thesis: "Without secure APIs, rapid innovation would be impossible" (PDF p. 3).
- A general web-application Top 10 still has its place, but the particular nature of APIs calls for a list of its own. API security is defined as the strategies and solutions used to understand and mitigate the vulnerabilities and risks that are specific to APIs (PDF p. 3).

## How to read the document
- Readers who know the OWASP Top 10 project will recognise the same layout; both documents are written for readability and adoption (PDF p. 3).
- Newcomers to the series are advised to read the API Security Risks section (A00-006) and the Methodology and Data section (A11-003) before the list itself (PDF p. 3).
- Questions, comments and ideas are collected in the project's GitHub repository (issues and a contributing guide); the document itself is published on the OWASP project page and on GitHub. Contributors are listed in the Acknowledgments (PDF p. 3).
