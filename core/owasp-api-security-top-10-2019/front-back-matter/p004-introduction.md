# Introduction
(Source: PDF p. 4)

## What the section covers
A short welcome to the first edition of the OWASP API Security Top 10 (2019): what it is modelled on, why it exists, who it is for, and how it was built.

## Meaning
- This is the first edition of the list. It deliberately mirrors the OWASP Top 10 series in structure because that format is built for readability and adoption. Readers new to the series are pointed to the OWASP API Security Project wiki page before going deeper into the risks (PDF p. 4).
- APIs are described as playing a very important role in the architecture of modern applications. Because security awareness and innovation advance at different speeds, the document chooses to concentrate on the common API security weaknesses rather than on everything that could go wrong (PDF p. 4).

## Why it matters
- The primary goal is education. The intended readers are everyone involved in developing and maintaining APIs: developers, designers, architects, managers and whole organisations (PDF p. 4).

## How it was built
- The Methodology and Data section (A11-003) describes how this first edition was put together. The authors want future editions to involve the security industry through a public call for data; for now, they invite questions, comments and ideas through the project's GitHub repository and mailing list (PDF p. 4).
