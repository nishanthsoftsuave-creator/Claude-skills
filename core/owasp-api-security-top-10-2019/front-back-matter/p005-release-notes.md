# Release Notes
(Source: PDF p. 5)

## What the section covers
The edition history of the document (there is only one edition at the time of writing), the planned update cycle, and why the authors felt an API-specific list had become necessary.

## Meaning
- This is the first OWASP API Security Top 10 edition. The authors plan to update it periodically, every three or four years (PDF p. 5).
- Unlike this edition, future editions are meant to rest on a public call for data that brings the wider security industry into the effort. The Methodology and Data section (A11-003) explains how this edition was built instead, and the API Security Risks section (A00-006) explains how risks are scored (PDF p. 5).

## Why it matters
- The release notes stress that application architecture has changed significantly over the last few years. APIs now carry much of the weight in the architecture of microservices, Single Page Applications (SPAs), mobile apps and IoT devices, which is what made a dedicated awareness document necessary (PDF p. 5).
- The document is the product of volunteer effort; the contributors are listed in the Acknowledgments (PDF p. 5).

## Time-sensitive statements
- "First edition" and the three-to-four-year update plan describe the state in 2019 (PDF p. 5).
- SUPPLEMENTARY: OWASP has since published a 2023 edition of the API Security Top 10 (source: the OWASP API Security Project). Several entries were renamed, merged or replaced in that edition, so when a current project is reviewed, confirm which edition the team is measuring against before citing a risk number from this module set.
