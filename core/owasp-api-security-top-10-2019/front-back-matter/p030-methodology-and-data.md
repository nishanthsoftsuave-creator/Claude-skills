# Methodology and Data
(Source: PDF p. 30)

## What the section covers
How the 2019 list was assembled: the data it rests on, the role of practitioner opinion, how risks were scored, and when and where the draft was presented.

## Meaning
- Overview: the application-security industry had not focused specifically on the newer application architecture in which APIs are central, so a public call for data would have been hard to run. Despite there being no public data call, the list still rests on publicly available data, the contributions of security experts and open discussion with the security community (PDF p. 30).

## How it works: the process
1. **Phase one.** A group of security experts collected, reviewed and categorised publicly available data about API security incidents, drawn from bug bounty platforms and vulnerability databases over a period of one year. This data was used for statistical purposes (PDF p. 30).
2. **Phase two.** Security practitioners with penetration-testing experience were asked to draw up their own Top 10 lists (PDF p. 30).
3. **Scoring.** Risk analysis used the OWASP Risk Rating Methodology; the practitioners discussed and reviewed the scores (PDF p. 30; scales in A00-006).
4. **First draft.** It came from the consensus between the phase-one statistics and the practitioners' lists, and was then submitted to another group of practitioners with relevant API security experience for review (PDF p. 30).
5. **Publication.** The list was first presented at the OWASP Global AppSec Tel Aviv event in May 2019 and has been on GitHub for public discussion and contributions since (PDF p. 30). The contributors are named in the Acknowledgments section (PDF p. 30).

## Limitations and failure modes
- The ranking therefore blends one year of public incident data with practitioner judgement, not a broad industry data call (PDF p. 30). The authors intend a public call for data in later editions; that plan is stated in A00-005 and A00-004.

## Time-sensitive statements
- The data window, the presentation date and the description of the process all date from 2019 (PDF p. 30).
