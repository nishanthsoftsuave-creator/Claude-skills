# Index: term to module map
(Source: PDF pp. 932-988)

## What this module is
The book ends with an alphabetical index. Each index entry names a term and the section headings it points to (the book's Index lists headings, not page numbers) (PDF p. 932). This module keeps that structure as a lookup: for each term it gives the matrix row ids of the modules that cover the headings the entry points to. Sub-entries are shown as `parent > child`. A reference to a range of headings (`A-B`) is expanded to the rows between the two headings in book order. A heading below the outline depth was found by locating it as a line of the section text. The mapping was generated by script and spot-checked by an independent reviewer; where the Index's own lines wrap, an entry can carry a wrong parent, some parent-only rows are wrap artefacts, and a reference on a continuation line can be lost (an independent check of 80 sampled entries found 78 correct).

How to use it: look up a term, then open the listed modules (their files are listed in `core/ai-engineering-building-applications-with-foundation-models/index.md`). `(several candidates)` means the heading could belong to more than one section, so each candidate is listed without expanding ranges. `(heading only; see sub-entries)` marks a parent term with no direct references. `unmapped` marks an entry whose references could not be resolved (listed in `coverage/known-gaps.md`).

Entries: 1042; resolved to modules: 958; parent-only: 36; unmapped: 48.
