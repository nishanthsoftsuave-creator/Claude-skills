# Use Case: Coding
(Source: PDF pp. 64-66)

## What the section covers
Why coding is the most popular generative AI use case, the commercial and open source evidence, the specialized coding tasks tools target, the debate over whether AI will replace software engineers, and McKinsey's data on where AI helps developers most.

## Figure 1-8, printed at the top of this page (belongs to the lead-in discussion)
Figure 1-8 (rendered and read) backs the lead-in's claim that companies deploy internal-facing applications faster (PDF p. 64). Its question is how willing enterprises are to use LLMs for different use cases, measured as the percentage of enterprises experimenting with a use case that have deployed it to production. Internal-facing: text summarization 62%, enterprise knowledge management 60%. In the middle group: customer service 59%, marketing copy 53%, software development 53%, contract review 45%. External-facing: external chatbot 39%, recommendation algorithm 39%. The caption says companies are more willing to deploy internal-facing applications.

## Why coding leads
- In multiple generative AI surveys coding is "hands down the most popular use case". Two reasons: AI is good at coding, and early AI engineers are coders who are more exposed to coding challenges (PDF p. 64).
- Consistent with the open source survey in the preceding section, coding was the largest category (see C01-005).

## Evidence of success (PDF pp. 64-65)
- GitHub Copilot, a code completion tool and one of the earliest production successes of foundation models, passed $100 million in annual recurring revenue only two years after launch.
- As of the author's writing, AI coding startups had raised hundreds of millions of dollars: Magic raised $320 million and Anysphere $60 million, both in August 2024.
- Open source coding tools gpt-engineer and screenshot-to-code each reached 50,000 GitHub stars within a year, with many more appearing quickly.

## Specialized coding tasks and example tools (PDF p. 65)
- Extracting structured data from web pages and PDFs (AgentGPT).
- Converting English to code (DB-GPT, SQL Chat, PandasAI).
- Generating website code from a design or screenshot (screenshot-to-code, draw-a-ui).
- Translating between programming languages or frameworks (GPT-Migrate, AI Code Translator).
- Writing documentation (Autodoc).
- Creating tests (PentestGPT).
- Generating commit messages (AI Commits).

## Will AI replace software engineers?
- AI clearly handles many software engineering tasks; the open question is whether it can automate the whole job (PDF p. 65).
- One end of the spectrum: NVIDIA CEO Jensen Huang predicts AI will replace human software engineers and says we should stop telling kids to learn to code. In a leaked recording, AWS CEO Matt Garman said most developers will stop coding in the near future, though he framed it as their jobs changing rather than ending (PDF pp. 65-66).
- Other end: many engineers are sure AI will never replace them, for technical and emotional reasons, since people dislike admitting they can be replaced (PDF p. 66).
- The book's own view: software engineering is many tasks and AI is better at some than others. McKinsey researchers found AI can make developers about twice as productive on documentation and 25-50% more productive on code generation and refactoring, with minimal gains on highly complex tasks (PDF p. 66). The accompanying Figure 1-9 is printed at the top of the next page (the section continues there, so no page cite). As rendered, it is a bar chart of average time reduction in task completion using generative AI (data by McKinsey): code documentation 45-50%, code generation 35-45%, code refactoring 20-30%, high-complexity tasks under 10%. Its caption says AI helps developers most on simple tasks and less on highly complex ones. The text says "twice as productive" and "25-50%" while the figure prints time-reduction ranges; the two are recorded as printed and differ.
- Developers of AI coding tools told the author that AI is much better at frontend than backend development (PDF p. 66).

## Implications
Whether or not AI replaces engineers, it makes them more productive, so companies can do more with fewer engineers. The text then adds that AI could also disrupt the outsourcing industry, because outsourced tasks tend to be simpler ones outside a company's core business. This closing paragraph is printed on the next page, so the Coding section continues there and it carries no page cite.

## When and how to apply
INTERPRETATION: the productivity data suggests prioritizing AI assistance for documentation, code generation and refactoring rather than expecting it to handle highly complex engineering tasks.
