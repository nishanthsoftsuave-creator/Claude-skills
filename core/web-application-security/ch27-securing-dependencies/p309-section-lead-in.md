# Secure Integration Techniques (lead-in)
(Source: PDF p. 309, continued on PDF p. 310)

## What the section covers
The short introduction to the second half of Chapter 27: how to integrate third-party code securely, seen from the side of the application owner.

## Meaning
- Part II compared the ways a web application can integrate third-party code, weighing the pros and cons of each from the viewpoint of an onlooker or attacker (PDF p. 309).
- The book now takes the viewpoint of an application owner and asks a single question: what are the most secure ways of integrating a third-party dependency? (PDF p. 310).

## Why it matters
INTERPRETATION: the question frames the two techniques that follow: keeping the third-party code separate from the main application (WAS-C27-006) and managing packages so that only audited versions are used (WAS-C27-007).

## Relations
The integration methods themselves were introduced in WAS-C15-002.
