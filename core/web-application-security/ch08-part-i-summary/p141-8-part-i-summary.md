# Part I Summary
(Source: PDF pp. 141-142)

## What the section covers
The closing message of the Recon part: keep recon methods current, automate them and write them down.

## Meaning
- By this point the reader should understand why web application recon is done and have a few techniques to start a recon toolkit (PDF p. 141).
- Recon methods keep changing and it is hard to say which are best, so you should keep looking for new ones, particularly those that can be done quickly and automated to save repeated manual work (PDF p. 141).

## Why it matters
- Old methods can go stale and need replacing. The book's example is web server packages that have grown more careful about leaking the server software and version number (PDF p. 141).
- Basic skills probably never vanish, but new technologies appear. You need ways to map them as well as to understand current and legacy technology (PDF p. 141).

## When and how to apply
- Part I stressed writing down and organising your findings. The book also advises recording the techniques you use, because your toolkit will grow to cover many technologies, frameworks, versions and methods (PDF p. 141).
- Recorded techniques are easier to turn into automation later or to teach as a mentor. Strong recon methods are too often kept as tribal knowledge, and the book encourages sharing new ones with the wider security community (PDF p. 141).
- The techniques you discover may help penetration testers and may also lead to progress in application security. How you collect, record and share them is up to you, and the author hopes the foundations become a cornerstone of your toolkit (PDF p. 142).
