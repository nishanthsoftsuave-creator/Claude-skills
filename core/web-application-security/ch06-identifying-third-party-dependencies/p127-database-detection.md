# Database Detection
(Source: PDF p. 127; the MongoDB description and examples finish on PDF p. 128)

## What the section covers
Inferring which database backs an application, mainly by looking at the shape of primary keys that appear in network traffic.

## Meaning
- Most web applications keep users, objects and other persistent data in a server-side database such as MySQL or MongoDB. Very few teams build their own, because storing and retrieving large amounts of data reliably is hard (PDF p. 127).
- If database error messages reach the client, the same approach as for server packages works, but this is often not the case, so another route is needed (PDF p. 127).
- A primary key is a key in a table (SQL) or document (NoSQL) generated automatically when an object is created and used for fast lookup. Generation differs between databases and can sometimes be configured, for example to get shorter keys for URLs (PDF p. 127).

## How it works
1. Learn how default keys are generated by a few major databases. Unless the default was overridden, enough network requests will usually reveal the database type (PDF p. 127).
2. MongoDB example: by default each document gets an _id field produced by a low-collision algorithm. The book describes it as a hexadecimal-compatible string of length 12. The documented generator is the ObjectId class; each id is exactly 12 bytes, and the first 4 bytes are the Unix timestamp in seconds (PDF p. 127). The remaining 5 bytes are random and the last 3 form a counter that starts from a random value (PDF p. 128).
3. The example id 507f1f77bcf86cd799439011 has 24 hex characters, which is 12 bytes. INTERPRETATION: "length 12" in the text means 12 bytes, not 12 characters.
4. The spec has helper methods such as getTimestamp(), but they are not available when you only observe client traffic, so you look through the payloads you capture for 12-byte strings that look like this (PDF p. 128).
5. Keys appear in routes like GET users/:id, in a body such as PUT users with an id, in a query parameter such as GET users?id, and sometimes inside metadata or a user object that also lists username, email, role and biography (PDF p. 128).
6. When a value is confirmed as a primary key, compare it with key-generation algorithms in documentation. If several databases share an algorithm, for example sequential integers, combine with another technique such as forcing error messages (PDF p. 128).

## Limitations
Simple key schemes cannot tell databases apart. Overridden key generators defeat the technique.
