# Preface - Suggested Background
(Source: PDF p. 18)

## What the section covers
Who the book is written for in terms of experience, and why the author chose the label "intermediate-level background in software engineering" for the required skill level.

## Meaning
- The potential audience is described as quite broad, and the style and examples are aimed at anyone with an intermediate-level software engineering background (PDF p. 18).
- The author admits that "intermediate" differs a lot from person to person. For a highly technical person the requirement might be closer to beginner: a system administrator with enough web development or scripting experience could read the book and follow all the examples (PDF p. 18).

## What the reader must be able to do
- The book contains examples that need both client-side and server-side coding knowledge. Knowing only one of the two is not enough for a deep understanding of those examples (PDF p. 18).
- It also discusses basic client/server networking over HTTP (PDF p. 18).
- Later chapters bring in software architecture, specifically ways of integrating in-house software with third-party software while limiting the security risk (PDF p. 18).

## Why the level was chosen
Because so many topics are covered, the author defines the required level as "intermediate" rather than "beginner". The reason given is that the book would not suit someone with no experience or knowledge of writing production-quality software applications (PDF p. 18).
